# Process Inbox

**Purpose:** turn frictionless captures into organised, linked, retrievable
material without losing the originals.

**Required context first:** `vault/CLAUDE.md`; list `vault/00 Inbox/`; for
each item, search the vault for related titles/content before deciding.

## Workflow (per item)

1. Identify what it is: idea, task, reference, source material, project
   material, knowledge, ephemera.
2. Search for related notes, the owning project/area, and probable duplicates.
3. Decide destination:
   - project material → that project's folder (link from README where useful)
   - reusable insight → `03 Knowledge/` (extend an existing note if one fits)
   - source/reference → `04 Resources/` with provenance
   - actionable item → add to the relevant project README's Next Actions
   - not yet placeable → leave in Inbox, add a one-line note of what's unclear
4. Add links for relationships that will matter later.
5. Move (never delete) the item; keep the owner's original wording.

## Contract

- Level: ORGANISE (moves + links). Editing README Next Actions is UPDATE —
  do it only for clearly actionable items, verbatim to the capture's intent.
- Prohibited: deleting items, merging away originals, rewriting the owner's
  words, bulk-creating properties or tags.
- Uncertain about destination or duplicate status → leave in place and flag;
  never guess silently.

## Output

Concise report: items processed → where each went and why; duplicates
suspected; actions extracted; items left in Inbox and what decision they need.
